# 术语与排版

仅在需要处理术语、错词、标点、留白或大小写时读取本文件。所有规则只作用于可见正文，不作用于代码、路径、字段、命令、配置项和用户指定的固定字面量。

## 术语原则

- 同一概念使用同一首选术语。
- 优先采用目标项目术语表和产品官方写法。
- 不因为追求词汇变化而替换同义词。
- 词语可能有多个合法含义时，先判断语境，不做全局替换。
- 项目专属术语放在目标项目的覆盖文件中。

## 空泛表达与黑话

以下词语容易掩盖具体动作。只有在有明确业务定义、属于正式术语、引用原文或用户要求保留时才使用：

- `赋能`
- `抓手`
- `闭环`
- `沉淀`
- `对齐`
- `对标`
- `拉通`
- `打通`
- `协同`
- `联动`
- `洞察`
- `赛道`
- `心智`
- `调性`
- `战役`
- `链路`
- `势能`
- `兜底`
- `落盘`
- `收口`
- `透传`

优先说明它实际指什么：

- `赋能` -> `提供`，或直接写提供的能力
- `抓手` -> `关键措施`
- `闭环` -> `完整流程`，或列出开始、处理和完成条件
- `沉淀` -> `形成`、`积累`、`保存`
- `对齐` -> `统一`、`确认一致`
- `拉通` / `打通` -> `连接`、`贯通`
- `洞察` -> `分析结论`
- `兜底` -> 写出失败后的具体保障机制
- `落盘` -> `写入文件`、`保存到本地`
- `透传` -> `原样传给下游`

以下词语依赖语境，不应由检查器自动替换：

- `场景`
- `生态`
- `体系`
- `路径`
- `触点`
- `卡点`
- `布局`
- `矩阵`
- `颗粒度`
- `复盘`
- `梳理`
- `输出`
- `提炼`

保留内部术语时，在首次出现处说明实际含义，避免连续堆叠多个术语。

## 标点

- 中文正文默认使用全角中文标点。
- 中文引号默认使用直角引号 `「」`；项目、地区、出版或引用规范可以覆盖。
- 避免连续感叹号、省略号和口号式断句。
- 完整句式的列表项统一使用句号；短语型列表项可以不加句号，但同一列表保持一致。
- 并列词语使用顿号，并列分句根据层级使用逗号或分号。
- 冒号后应当确有解释、列举或引用，不要把每句话都拆成冒号列表。
- 破折号、括号和斜线只在关系明确时使用，不用它们代替句子组织。

## 称呼

- 技术文档默认不直接称呼读者，优先使用无主句或明确角色。
- 根据语境使用 `开发者`、`技术负责人`、`实施人员`、`业务负责人`、`产品经理`。
- `你`、`您`、`同学` 属于风格提示，不是普遍语言错误；消费产品、帮助文本或品牌规范可以允许第二人称。

## 中文与英文、数字之间的留白

在可见正文中，中文与可读的半角英文单词、英文缩写、独立数字和版本号之间通常保留空格：

- `获取批量 ID`
- `HTTP 请求`
- `版本 2.0`
- `AI 服务`
- `与 PM 协作`

不要机械处理：

- 行内代码和代码块
- JSON 键名
- URL 和 API 路径
- 数据库字段名
- 命令、配置项、占位符和正则表达式
- 直接镜像接口定义的表头
- 产品官方拼写和用户指定字面量

数字排版还应检查：

- 日期、时间和时区是否完整
- 百分比与百分点是否混用
- 数值是否带有必要单位
- 区间上下界和包含关系是否明确
- 货币、温度、存储单位和千位分隔是否一致

## 段落换行与源文件行宽

中文 Markdown 段落在源文件中保持一段一行，不为了控制源码行宽在段落中间手动断行。长行交给编辑器软换行阅读。

取消硬换行的原因：

- 段落被手动断成多行后，源文件很碎，改写、比对和审阅都更难对照上下文。
- 软换行在多数渲染器中按空格处理，中文与英文边界上的断行会多出或吞掉空格。

保持一段一行的范围：

- 正文段落
- 列表项正文；列表层级、标记和缩进不变

以下内容保留原有换行：

- 围栏代码块和缩进代码块，包括写在列表标记之后的围栏和列表项内的缩进代码
- 表格的行结构
- 标题、Setext 下划线、分隔线和链接引用定义
- HTML 块按整块保留，包括多行 `<pre>` 和多行注释
- 引用块，它可能需要保持原文形态
- 行尾两个空格或反斜杠表示的显式换行

展开硬换行后，逐处复查拼接边界的留白：

- 中文与中文之间不加空格
- 中文与半角英文、数字之间加一个空格，例如 `作为 ASR`、`的 stdio 模式`
- 全角标点两侧不加空格，例如 `说明，API 返回`
- 行内代码、链接和强调标记按可见文字判断，例如 `详见 **接口说明**文档`

需要批量处理时使用 `scripts/unwrap_md_paragraphs.py`。工具只处理拼接边界，不修改段落内部已有的留白、标点和措辞，结果仍需人工复核。

## 技术术语大小写

以下是常见推荐写法，不应覆盖项目或产品的官方命名：

- `id` / `Id` -> `ID`
- `http` / `Http` -> `HTTP`
- `url` / `Url` -> `URL`
- `json` / `Json` -> `JSON`
- `api` / `Api` -> `API`
- `ai` / `Ai` -> `AI`
- `javascript` -> `JavaScript`
- `typescript` -> `TypeScript`
- `llm` / `Llm` -> `LLM`
- `aigc` / `Aigc` -> `AIGC`
- `rag` / `Rag` -> `RAG`
- `chatgpt` / `Chatgpt` -> `ChatGPT`
- `openai api` / `OpenAI api` -> `OpenAI API`
- `python` -> `Python`
- `nodejs` -> `Node.js`
- `github` -> `GitHub`
- `gitlab` -> `GitLab`
- `postgresql` -> `PostgreSQL`
- `grpc` -> `gRPC`
- `graphql` -> `GraphQL`
- `websocket` -> `WebSocket`
- `yaml` -> `YAML`
- `xml` -> `XML`
- `jwt` -> `JWT`

以下写法依赖语境，只能提示人工确认：

- `JS`：简短界面或既有名称中可能合理，正式正文可写 `JavaScript`
- `H5`：可能指移动 Web 活动页，不等同于 HTML5 标准
- `Postgres`：可能是项目采用的正式简称
- `OAuth`：可能指协议家族，不能自动补成 `OAuth 2.0`
- `k8s`：正式文档可写 `Kubernetes`，命令、标签和社区语境可能保留

## 高频错词与语境词

可以作为确定错误处理：

- `阀值` -> `阈值`
- `布署` -> `部署`
- `反回` -> `返回`
- `回朔` -> `回溯`
- `做为` -> `作为`
- `embeding` -> `embedding`
- `提示工程学` -> `提示工程`

必须结合语境判断：

- `登录系统`，但可以说 `登陆月球`
- `配置参数`，但可以说 `配制溶液`
- `截至 4 月 12 日`，但可以说 `截止日期`
- `启用功能`，但可以说 `起用新人`
- `标识字段`，但可以说 `在图中标示位置`
- 技术能力通常写 `实时通信`，但 `即时` 在其他语境中可能正确
- `认证` 表示确认身份，`授权` 表示授予权限

## 数量与逻辑

- `缩小了 3 倍` -> `缩小到原来的 1/3` 或写明减少比例
- `从 20% 增长到 30%`：增加 10 个百分点，相对增长 50%
- `转化率提升了 5%`：确认是提升 5% 还是 5 个百分点
- `翻了 1 倍` -> `变为原来的 2 倍`
- `不超过 100 以上` -> `不超过 100`
- `预计大约在 3 点左右` -> `预计 3 点左右`

修正表达时不得自行补充原文没有的基数、年份、期限或测量结果。
